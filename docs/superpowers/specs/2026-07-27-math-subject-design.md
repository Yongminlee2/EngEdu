# 삐약공부 — 수학 과목 추가 설계

2026-07-27. 영어 전용이던 앱(삐약영어)에 수학을 더해 **삐약공부**로 확장한다.
유치원(6세)부터 고3까지 학년별 사다리를 만들고, 시작 화면에서 과목을 고른다.

## 목표와 제약

- 시작 화면(대문)에서 **영어 / 수학**을 고른다
- 유치원~고3 **13개 학년**을 단계별로, 학년당 800~1,500문제 (합계 1.5만+)
- 초등 고학년까지는 **그림·사물 이미지 위주, 큰 버튼, 소리로 읽어주기**
- 진행도·지갑·하트·스트릭은 기존 데이터를 그대로 보존한다 (applicationId 유지)
- 이미지 파일을 쓰지 않는다 — 이모지와 Canvas 드로잉으로 모든 그림을 만든다

## 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 문제 생성 | 생성기로 **미리 구워 팩에 고정** + 문장제·개념은 손저작 | 문제 ID가 고정돼야 오답노트·복습·진행도·"첫 클리어만 코인"이 작동한다. 실시간 생성은 이 시스템을 전부 깨뜨린다 |
| 과목 분리 | 시작 화면 → 과목별 홈 | "대문에서 고르기" 요구에 맞고, 화면당 정보량이 줄어 아이가 헤매지 않는다 |
| 공유 자원 | 지갑·하트·스트릭·칭호·일일목표는 **과목 공유** | 아이가 뭘 풀든 용돈은 한 지갑에 모이는 게 자연스럽다 |
| 분리 자원 | 실력 대시보드·코스 진행도는 **과목별** | 영어 실력과 수학 실력은 다른 축이다 |
| 앱 이름 | 삐약영어 → **삐약공부** (applicationId 는 `com.piyak.english` 유지) | 패키지를 바꾸면 재설치가 되어 진행도·지갑이 전부 사라진다 |

## 문제 모델 — 유형을 늘리지 않고 "그림 명세"를 붙인다

영어 문제 유형이 이미 9종이다. 수학마다 새 타입을 만들면 감당이 안 되므로 **단일 `Math` 타입**에
그리기 명세(`visual`)와 입력 방식(`input`)을 필드로 둔다.

```json
{
  "id": "m00123", "type": "math",
  "prompt": "사과가 모두 몇 개일까요?",
  "visual": { "kind": "emoji", "emoji": "🍎", "count": 7 },
  "input": "number",
  "answer": "7",
  "explain": "하나씩 세어 보면 7개예요. 🍎🍎🍎🍎🍎🍎🍎"
}
```

**visual.kind** (Canvas·이모지로 그린다. 이미지 파일 없음)

| kind | 그림 | 쓰이는 곳 |
|---|---|---|
| `emoji` | 이모지 n개를 격자로 | 수 세기 |
| `emoji_op` | 🍎🍎 ＋ 🍎 형태 | 한 자리 덧셈·뺄셈 |
| `array` | m행 n열 배열 | 곱셈의 의미, 나눗셈 |
| `shapes` | 원·삼각형·사각형·오각형 도형 | 모양 알기, 다각형 |
| `clock` | 시침·분침 있는 시계 | 시각 읽기 |
| `fraction` | 원/막대를 나눈 그림 | 분수 개념, 약분 |
| `number_line` | 수직선과 눈금 | 수의 크기, 정수, 소수 |
| `bar_graph` | 막대그래프 | 자료 해석 |
| `angle` | 각도 그림 | 각의 크기 |
| `compare` | 두 그룹 나란히 | 많다/적다, 크다/작다 |
| `none` | 그림 없음 | 중·고등 계산 문제 |

**input**: `number`(숫자 키패드) / `choice`(4지선다) / `text`(식·문자 답)

학년이 올라갈수록 `none` + `choice/text` 비중이 커지고, 저학년은 그림 + `number`가 대부분이다.

```
  MathVisualView.kt    visual 명세를 받아 Canvas 로 그리는 뷰 (도형·시계·분수·그래프)
  NumberPadView.kt     아이용 큰 숫자 키패드 (0~9, ., /, -, 지우기)

```

**기존 코드 접합**
- `ContentRepo.TRACK_IDS` → `Subject.tracks(subject)` 로 대체. 팩 파일명은 `math_g1.json` 처럼 접두사로 구분
- `LessonActivity` 는 이미 597줄이라 수학 렌더링을 안에 넣지 않는다. `Question.Math` 는
  `MathVisualView` + `NumberPadView` 조합으로 그리고, 채점은 `Grader.gradeMath()` 로 분리
- 실력 대시보드는 과목별로 6영역을 표시 (수학: 연산·수감각·도형·측정·자료·문장제)

## 채점

- `number` 입력: 공백 제거 후 수치 비교. 분수는 `3/4` 형태 허용, 소수·분수 동치 인정(0.75 == 3/4)
- `text` 입력: 영어의 정규화 채점기를 재사용하되 수식용 정규화(공백·곱셈기호 `x`↔`*`) 추가
- `choice`: 기존 4지선다 로직 그대로

## 아이용 배려 (초등까지)

- 문제 텍스트를 **TTS 로 읽어준다** (한국어 음성). 문제 화면 진입 시 자동 1회 + 🔊 버튼
- 숫자 키패드는 화면 폭의 큰 비율을 차지하는 큼직한 버튼
- 선택지는 그림·숫자를 크게, 4개를 2×2 격자로
- 정답 시 색종이·병아리 리액션(알파벳 쓰기에서 만든 연출 재사용)

## 데이터·호환

- DB 스키마 변경 없음. `progress`·`wrongs` 는 lesson_id / qid 로 관리되므로 수학 팩이 늘어도 그대로 동작
- 새 meta 키: `subject_last`(마지막에 고른 과목), `math_placement_level`
- 기존 사용자는 앱 이름과 시작 화면만 달라지고 데이터는 100% 유지

## 테스트

- 생성기 산출물 전수 검증(기존 `ContentPackTest` 확장): 파싱·정답 형식·선택지 중복·visual 명세 유효성
- `MathGraderTest`: 분수/소수 동치, 공백·기호 정규화, 오답 처리
- `SubjectTest`: 과목별 트랙 목록·팩 경로 매핑
- 학년별 문제 수 하한 검증 (학년당 최소 400문제 — 대시보드 레벨이 실제로 오를 수 있어야 한다)

## 단계

1. **1단계(이 스펙)**: 과목 선택 구조 + 수학 엔진·렌더러 + 유치원~초6 콘텐츠
2. 2단계: 중1~3
3. 3단계: 고1~3

각 단계가 끝나면 바로 쓸 수 있는 상태가 된다.
