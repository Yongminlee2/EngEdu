# 삐약공부 🐥

혼자 쓰는 듀오링고 스타일 학습 앱. **영어와 수학**을 대문에서 골라 공부한다.
영어는 알파벳 쓰기부터 토익·토플까지, 수학은 유치원부터 고3까지 단계별로 올라간다.
완전 오프라인 문제은행 내장(말하기 채점만 인터넷 권장).

| | |
|---|---|
| 플랫폼 | Android (minSdk 26, targetSdk 36), Kotlin + Views/ViewBinding |
| 내장 문제 | **27,484문제** · 2,863레슨 — 영어 15,450 · 수학 12,034 |
| APK | `삐약공부-v2.5.apk` 약 8.0MB |
| 테스트 | JUnit 82건 (채점 엔진 · 게임 규칙 · 상호작용 · 콘텐츠 전수 검증) |

## 주요 기능

**📘 영어 (10트랙 · 15,450문제)**
- 🎠 초등영어 놀이터 — 알파벳 찾기·파닉스·사이트워드·그림 낱말·쉬운 문장 (그림 위주)
- 목적별: 기초 차근차근(10단계) · 일상/여행(27장면) · 토익 · 토플
- 영역별: 듣기 · 말하기 · 쓰기 · 문법 · 독해 집중 훈련
- ✏️ **알파벳 손글씨** A~Z 대소문자 52자 — 병아리가 획순을 보여주고, 여러 번 쓸수록 별이 늘어난다

**🔢 수학 (13트랙 · 12,034문제)** — 유치원부터 고3까지 학년별
- 그림으로 배운다: 이모지 수 세기, 곱셈 배열, 시계, 분수 원그래프, 수직선, 막대그래프, 각도
- 아이용 큰 숫자 키패드 · 2×2 큰 보기 버튼 · 🔊 버튼을 누르면 한국어로 읽어준다(자동 재생 안 함)
- 📝 **연습장** — 문제 위에 겹쳐 식을 쓰거나 그림에 표시하며 푼다
- 👆 **짚어 세기** — 그림의 사물을 하나씩 터치하면 세는 순서가 붙는다
- 저학년(유치원~초3)은 키패드 대신 **버블을 탭**해서 답한다

**🎮 놀이터 (미니게임 3종)** — 움직이고 손가락으로 조작한다
- 🎈 풍선 터뜨리기 — 떠오르는 풍선 중 정답을 탭 (수학: 암산 / 영어: 낱말 듣고 그림 찾기)
- 🧺 바구니에 담기 — 사물을 끌어다 개수만큼 담기 (수 세기)
- 🔗 선으로 잇기 — 좌우를 손가락으로 이어 긋기 (식↔답, 그림↔낱말)
- 목숨 3개 · 90초 · 점수 · 별 3단계 · 난이도 3단계

**✋ 일반 문제도 만지는 방식** (놀이터가 아닌 평소 학습에서)
- 짧은 4지선다는 **둥둥 떠다니는 버블**을 탭 — 시간 압박 없이 움직임과 터치감만
- 짝 맞추기는 **손가락으로 선 잇기**
- 수학 그림은 **하나씩 짚어 세기**, 저학년은 버블 탭, 문제 위에 **연습장**으로 필기

**공통**
- **문제 유형 10종**: 4지선다, 듣고 고르기(TTS), 받아쓰기, 단어 타일 어순 배열, 한→영 영작,
  단어-뜻 매칭, 말하기(음성인식 자동채점), 2인 대화 듣기, 지문 독해, 수학(그림+숫자/식 입력)
- **레벨테스트**: 25문항 적응형 (영어 10단계 / 수학 13학년) → 해당 구간까지 자동 해금.
  설정의 "자유 이동 모드"로 전체 해금도 가능
- **성취**: 영역별 실력 Lv.0~10(영어 6 + 수학 6) · 칭호 10단계 · 오늘의 목표 · 배지 24종 ·
  하트 5개(30분당 1개 회복) · 스트릭 달력 · 오답 복습
- **용돈 지갑**: 첫 시도 정답 1문제 = 10원, 레슨 첫 클리어에만 지급(반복 파밍 불가).
  상점(하트·힌트권·스티커·테마) + **부모 PIN으로 잠그는 현금 지급**
- 폰 내장 TTS(영어 원어민 + 한국어)와 구글 음성인식 사용 — 별도 서버·계정·인터넷 권한 없음

## 빌드

```
gradlew.bat :app:assembleDebug          # APK 빌드
gradlew.bat :app:testDebugUnitTest      # 단위테스트 (GRADLE_USER_HOME=C:/gradle-home 필요)

node tools/gen.js                 # 영어 문제팩
node tools/gen_elem_english.js    # 초등영어 놀이터
node tools/gen_math.js            # 수학 13학년
```

- 실기기 설치: `adb install -r 삐약공부-v2.5.apk`

## 콘텐츠 파이프라인

문제는 **미리 구워서 팩에 고정**한다. 문제 ID가 고정돼야 오답노트·복습·진행도·
"레슨 첫 클리어에만 용돈"이 전부 맞물린다(실시간 생성은 이 시스템을 깨뜨린다).

```
content/                     ← 영어 원천 데이터 (직접 편집)
  vocab_L1..L10.tsv            레벨별 어휘 1,170단어 (단어/품사/뜻/예문/예문해석)
  sentences.tsv                문장 355개 · grammar.jsonl 문법 250문항
  dialogues.json               일상·여행 대화 27장면
  reading.json                 짧은 독해 지문 24편 (레벨 2~10)
  toeic.json / toefl.json      토익·토플 지문·문항
tools/
  gen.js                       영어 문제팩 (어휘 1단어 → 문제 4~5개 자동 전개)
  gen_elem_english.js          초등영어 놀이터 (알파벳·파닉스·그림 낱말 데이터 내장)
  math/{lib,elementary,middle,high,word}.js   수학 학년별 생성기
  gen_math.js                  수학 13트랙 + 배치고사
  gen_index.js                 팩 요약 색인 (시작 화면 성능용)
app/src/main/assets/packs/   ← 생성 결과 (트랙 22개 + 배치고사 2개 + index.json)
```

**문제 추가 방법**: `content/` 에 단어·문장·문법을 추가하거나 수학 생성기를 손본 뒤
해당 생성기 → `gen_index.js` 순으로 실행하고 재빌드. 시드 고정 난수라 재생성해도 결과가 같다.

## 채점 규칙 요약

- 타이핑: 소문자·구두점·유니코드 아포스트로피·축약형(I'm↔I am 등 40여 쌍) 정규화 후 비교.
  답이 5자 이상이면 편집거리 1, 11자 이상이면 2까지 "오타 인정" 정답 처리
- 말하기: 인식 문장과 토큰 단위 편집거리 → 4단어 이상 유사도 75%, 3단어는 1오차, 1~2단어는 정확히.
  음성인식 2회 실패 시 건너뛰기 버튼 표시(하트 차감 없음, 퍼펙트만 해제)
- 매칭: 오터치는 하트를 깎지 않고 퍼펙트만 깨뜨림 (재출제 무의미하므로)
- 오답: 하트 -1, 레슨 끝에 재출제(듀오링고 방식), 오답노트 적재 → 복습에서 2연속 정답 시 클리어
- 수학: `0.75 = 3/4 = 6/8`, `"12 cm" = 12`, `"1,200" = 1200` 을 모두 같은 답으로 인정.
  식 답은 공백·곱셈기호(×↔*)를 정규화해 비교

# 개발일지

## 1. 기획·설계

**목표 확정.** 듀오링고처럼 문제 풀이 → 레슨 통과 → 레벨 상승 구조의 개인용 영어 학습 앱.
요구사항 정리:

- 초1부터 성인까지, 듣기·말하기·읽기·쓰기·독해 전 영역
- 트랙: 기초(단계별) + 일상회화·여행 + 토익 + 토플 — 전부
- 레벨테스트로 시작 위치를 정하되, 원하면 아무 데나 골라 풀 수 있게
- 말하기는 음성인식 자동채점 (듀오링고 방식)
- 하트·스트릭·XP·배지·오답복습 게임 요소 전부
- 콘텐츠는 처음부터 대용량으로

**플랫폼 결정: 네이티브 안드로이드.** 세 가지 안을 비교했다.

1. ✅ 네이티브(Kotlin + Views) — 듣기(TextToSpeech)·말하기(SpeechRecognizer)가 OS에 붙어 있어
   가장 안정적. WordChain에서 검증한 빌드 레시피 재사용 가능. 오프라인 완결.
2. ❌ WebView 하이브리드 — 핵심인 TTS/STT를 JS 브리지로 연결해야 해서 가장 불안정해지는 구조.
3. ❌ Flutter — 폰 전용으로 결정났으므로 새 툴체인 도입은 과잉.

**콘텐츠 전략이 이 프로젝트의 승부처.** 1만 문제를 손으로 쓸 수는 없으므로 3단 구조로 설계:
① 레벨 태그된 원천 데이터(어휘 TSV·문장·문법·대화·지문)를 저작하고 → ② 생성기가 원천 1개당
문제 여러 개를 템플릿 전개(단어 1개 → 뜻고르기/역방향/듣기/받아쓰기/예문 활용 4~5문제) →
③ 12문제 단위 레슨, 5레슨 단위 유닛으로 자동 패킹. 원천만 늘리면 문제가 비례해서 늘어난다.

설계서를 `docs/superpowers/specs/` 에 확정하고 스캐폴드 커밋.

**디자인 컨셉: "아기자기·귀여움".** 크림(#FFF8E7) 배경 + 병아리 옐로(#FFD54F) 파스텔 팔레트,
병아리 마스코트(VectorDrawable 직접 제작 — 기본/만세/눈물 3종), 이모지 아이콘, "삐약!" 말투 피드백.
잠긴 레슨은 알(🥚), 열린 레슨은 병아리(🐥), 완료는 별(⭐)로 표시하는 레슨 지도.

## 2. 앱 구현

**엔진을 UI에서 완전히 분리해 순수 Kotlin으로 작성** (단위테스트를 위해 android 의존 제거):

- `Grader`: 정규화(소문자·구두점·축약형 전개) → 정확 일치 → 편집거리 기반 오타 인정.
  말하기는 토큰 레벤슈타인으로 WER 유사도 계산. 짧은 문장일수록 엄격하게(1~2단어는 정확 일치)
  — 안 그러면 "hello" 한 단어 문제가 아무 말이나 통과된다.
- `LessonSession`: 큐 기반. 오답이면 큐 끝에 재출제 + 하트 차감. 매칭·말하기 건너뛰기용
  `submitNoPenalty`(하트·재출제 없이 퍼펙트만 깨는 제출)를 별도로 뒀다.
- `Economy`: 레벨 공식(레벨 n 누적 XP = 60·n(n+1)/2), 하트 회복(30분/1개, 날짜 바뀌면 풀회복),
  스트릭(오늘 안 했어도 어제까지 연속이면 유지).
- `Placement`: 3레벨에서 시작, 맞으면 +1 틀리면 -1, 최근 10문항 출제 레벨의 중앙값으로 배치.

**문제 플레이어(LessonActivity)가 제일 큰 파일.** 9개 유형별로 뷰를 갈아끼우는 구조.
어순 배열은 FlowLayout을 직접 만들어 단어 타일을 답안영역↔타일은행으로 토글 이동.
매칭은 좌우 컬럼 탭-탭 방식(오터치는 빨간 플래시 후 복구). 말하기는 마이크 버튼 →
RECORD_AUDIO 권한 → SpeechRecognizer(en-US) → 인식 문장과 유사도 % 표시.
오답복습 모드도 같은 액티비티가 겸한다(하트 미소모, 완료 시 하트 +1 보상).

**대화 듣기의 2인 연출**: TTS 엔진 하나로 화자 A는 피치 0.9, B는 1.2로 바꿔가며 문장 큐를
순차 재생(UtteranceProgressListener 체인). 실제로 들으면 남/녀 대화처럼 들린다.

### 이 PC 고유 빌드 함정 (다음 프로젝트를 위한 기록)

1. **`local.properties` 없음** → "SDK location not found". WordChain 것을 복사하면 끝.
2. **Kotlin은 블록 주석이 중첩된다!** KDoc에 `assets/packs/*.json` 같은 경로를 쓰면
   `/*`가 중첩 주석 시작으로 파싱돼 "Unclosed comment"로 파일 전체가 주석이 된다.
   에러 두 개(Question.kt, Content.kt)가 전부 이 원인. 주석에 글롭 경로 쓰지 말 것.
3. **MaterialCardView의 `app:cardCornerRadius` 등이 aapt 링크 실패**
   ("attribute auto:cardBackgroundColor not found"). 이 AGP 9.2.1 조합에서 XML의 res-auto
   속성 해석이 깨지는 케이스. 우회: XML은 shape drawable 배경, 코드 생성 카드는
   GradientDrawable로 통일. (테마 Material3 자체는 정상 동작)
4. **유닛테스트는 `GRADLE_USER_HOME=C:/gradle-home` 필수** — 홈 경로가 한글(C:\Users\사용자)이라
   테스트 워커 argfile 인코딩이 깨져 ClassNotFoundException으로 죽는 문제. WordChain 때 발견한
   함정 그대로.
5. **이 PC에 Python 없음** (WindowsApps 스텁만 있어서 실행하면 스토어가 열림). 도구 스크립트는
   Node(v24)로 작성했다. ffmpeg는 C:\ffmpeg\bin에 있음.

## 3. 콘텐츠 저작 (제일 오래 걸린 작업)

**어휘 1,170단어를 10레벨로 직접 저작.** 레벨 기준: L1 초1-2(apple, dog...) → L4 중1 →
L7 고1(abstract, adequate...) → L9 성인·토익(invoice, reimburse...) → L10 토플·학술
(paradigm, photosynthesis...). 전 단어에 품사·뜻·예문·예문 해석을 붙였다. 예문은 어순 배열
문제로 쓸 수 있게 3~10단어로 제한하고, 해당 레벨 이하 어휘로만 짓는 것을 원칙으로 했다.

**문장 355개** (기초 10레벨 문법 난이도 사다리 + 여행·일상 표현), **문법 4지선다 250문항**
(L1 be동사부터 L10 도치·가정법·학술 관용구까지 레벨당 25개, 전부 해설 포함), **대화 27장면**

**생성기(tools/gen.js)**: 시드 고정 난수(mulberry32)로 재현 가능한 출제. 6단어 그룹을

한 레슨에서 같은 단어를 여러 각도로 반복하게 했다. 오답 선택지는 같은 레벨 풀에서 중복 없이
추출. 생성 단계에서 전 문제 검증(선택지 4개·중복 없음·정답 인덱스 범위·타일 수 2~12)을 통과해야
팩이 나온다.

**결과: 8,206문제.**

```
basic: 유닛 127 · 레슨 575 · 문제 6739
daily: 유닛 12 · 레슨 69 · 문제 750
toeic: 유닛 9 · 레슨 35 · 문제 321
toefl: 유닛 8 · 레슨 34 · 문제 282
placement: 100문제
```

**효과음도 직접 합성** (tools/sfx.js): 정답 딩동(E6→A6 사인파), 오답 부저(220Hz 하강),
완료 팡파르(C5-E5-G5-C6 아르페지오), 그리고 삐약 소리(2.8~3.7kHz 스윕 칩 2회 — 진짜 병아리
소리 흉내). Node로 WAV 생성 → ffmpeg libvorbis 인코딩 → res/raw, 4개 합쳐 22KB.

## v1.2: 기능별 트랙 4개 + 성취 시스템

실기기로 써 보고 나온 두 번째 피드백: **"말하기·듣기·쓰기·문법을 따로 챕터로 하고 싶다"**,
그리고 **"성취감이 없다. 내가 지금 어느 레벨인지 모르겠다."** 둘 다 구조적인 문제였다.

### 기능별 트랙 5개 신설 (총 9개 트랙)

기존 트랙은 목적별(기초/여행/토익/토플)이라 "오늘은 듣기만 파고 싶다"가 안 됐다.
같은 원천 데이터를 **영역 관점으로 다시 엮은** 트랙을 추가했다. 문제 ID가 달라서
기존 트랙과 진행도가 따로 쌓인다.

| 트랙 | 구성 | 문제 |
|---|---|---|
| 🎧 듣기 집중 | 레벨별 단어 듣기 → 문장 받아쓰기 → 대화 듣기 | 2,812 |
| 🎤 말하기 집중 | 레벨별 예문 따라 말하기 → 실전 회화 → 여행 표현 | 1,460 |
| ✍️ 쓰기 집중 | 철자 쓰기 → 어순 조립 → 한→영 영작 | 1,823 |
| 📖 문법 집중 | be동사부터 도치·가정법까지 10단계 + 토익형 실전 | 300 |
| 📚 독해 집중 | 짧은 글(초등~고급) → 실용문 → 학술 지문 | 129 |

총 문제 수는 8,206 → **14,752개**가 되었다. 앞의 네 트랙은 원천 데이터를 한 줄도 늘리지 않고
생성기에 조립 함수만 추가해서 만들었다 — 파이프라인 설계의 이득을 그대로 본 셈.

독해만은 예외였다. 영역별 문제 수를 세는 테스트를 돌려 보니 **독해가 57문제뿐**이었는데,
Lv.3 달성에 누적 정답 60개가 필요하므로 **"만능 삐약이"(모든 영역 Lv.3) 배지가 수학적으로
달성 불가능**했다. 성취 시스템을 만들면서 자기 모순을 만든 셈이라, 레벨 2~10에 걸친 짧은
지문 24편(`content/reading.json`)을 새로 저작해 129문제로 늘렸다. 테스트에도
"모든 영역은 Lv.3을 찍을 만큼(70문제 이상) 있어야 한다"는 조건을 못 박아 재발을 막았다.

### 성취 시스템: "내가 지금 어느 레벨인지"

문제는 XP·레벨이 **하나의 숫자**뿐이라 무엇을 잘하고 못하는지 알 수 없다는 것이었다.
영역별로 쪼개서 보여주는 구조로 바꿨다.

- **영역별 실력 레벨(6종)**: 듣기·말하기·쓰기·문법·독해·어휘. 문제마다 `skill` 태그를
  붙이고(유형으로 자동 판별 + 문법은 팩의 명시 태그), 첫 시도 정답 수를 누적해 Lv.0~10 산출.
  레벨 n 도달 = 누적 정답 10·n(n+1)/2개 (Lv1=10, Lv5=150, Lv10=550).
- **홈 대시보드**: 여섯 영역이 각각 [이모지 · Lv · 진행바 · 정답률] 한 줄로. 안 해본 영역은
  "시작 전"으로 표시되고, 가장 약한 영역을 상단에 짚어 준다.
- **칭호 10단계**: 종합 실력(여섯 영역 평균)에 따라 🥚 알 속의 새싹 → 🐣 갓 깬 병아리 →
  🐥 삐약이 → 🐤 씩씩한 병아리 → 🐦 참새 → 🕊️ 비둘기 → 🦜 앵무새 → 🦉 부엉이 →
  🦅 독수리 → 👑 영어 마스터. 홈 최상단에 진행바와 함께 표시.
- **오늘의 목표**: 20/50/100/200 XP 중 선택, 홈에 진행 링(바). 달성하면 초록으로 바뀌고
  하루 한 번 달성 횟수로 집계된다.
- **레슨 결과 화면의 성장 리포트**: 이번 레슨으로 영역 레벨이 올랐는지, 칭호가 승급했는지,
  오늘의 목표 진행이 어떤지를 결과 화면에서 바로 알려준다.
- **배지 7종 추가** (총 19종): 목표 첫 달성/10회, 듣기·말하기·쓰기·문법 Lv.5 달성,
  모든 영역 Lv.3 이상(만능 삐약이).

통계 화면에도 영역별 상세 카드(정답/시도, 정답률, 다음 레벨까지 몇 문제)를 추가했다.

DB는 v2로 올리며 `skills` 테이블을 추가했다(기존 진행도는 onUpgrade로 보존).
단위테스트 11건 추가 — 레벨 임계값·진행률·종합 평균·칭호 승급·일일 목표, 그리고
**모든 문제에 유효한 영역 태그가 있는지, 기능별 트랙이 해당 영역 90% 이상인지**를 전수 검증.

## v1.3: 알파벳 손글씨 연습 (A~Z 따라쓰기)

아이가 쓸 수 있도록 **손가락·펜으로 알파벳을 직접 쓰는** 기능을 넣었다. 지금까지의 문제 풀이와
성격이 완전히 달라서(정답 선택이 아니라 운동 학습) 별도 화면과 자체 채점기가 필요했다.

### 글자를 "길"로 만든다

폰트 글리프의 외곽선을 쓰면 획순·방향을 알 수 없다. 그래서 **글자마다 중심선(skeleton)을
직접 좌표로 정의**했다. 획의 순서와 점의 순서가 그대로 쓰는 순서·방향이 된다.

```
'A' → [ (0.50,0.12)→(0.18,0.88),      // ① 왼쪽 대각선
        (0.50,0.12)→(0.82,0.88),      // ② 오른쪽 대각선
        (0.29,0.62)→(0.71,0.62) ]     // ③ 가로줄
```

곡선은 `arc(cx,cy,rx,ry,시작각,회전각)` 헬퍼로 생성한다(0°=오른쪽, 90°=아래, 양수=시계방향).
직선과 호를 이어 붙일 수 있어서 J의 갈고리, G의 꺾임, h의 어깨 같은 모양도 한 획으로 표현된다.
대문자 26 + 소문자 26 = **52자 전부 수작업 정의**. 소문자는 x-height(0.45), 베이스라인(0.88),
디센더(1.0) 기준을 지켜 p·q·y·g·j가 아래로 내려가게 했다.

### 채점: 길 위의 체크포인트를 순서대로 지나가기

`TraceView`(커스텀 View)가 획을 굵은 "길"로 그리고, 내부적으로 3.5% 간격으로 리샘플링한
체크포인트를 만든다. 손가락이 지나가면 **앞쪽 6개까지 훑어보며 가장 멀리 닿은 지점으로 전진**하되
뒤로는 가지 않는다 — 그래서 거꾸로 그리면 진행되지 않고, 자연스럽게 방향을 익히게 된다.
허용 오차는 길 폭의 13%로 넉넉하게(아이 손가락 기준). 손을 뗐을 때 92% 이상 지났으면 완성,
아니면 그 획만 초기화하고 판이 좌우로 흔들린다.

빠르게 그으면 터치 이벤트 사이가 벌어져 체크포인트를 건너뛰므로, `MotionEvent`의
**history(중간 좌표)까지 모두 검사**한다. 이걸 빼먹으면 빨리 그을수록 인식이 안 되는 버그가 된다.

### 귀여움 담당

- **병아리 시범 애니메이션**: `🐥 어떻게 써요?`를 누르면 병아리가 획을 따라 걸어가며 궤적을 남긴다.
  글자를 처음 열면 자동으로 한 번 보여준다.
- 시작점에 초록색 **①②③ 번호 뱃지**, 길 위에는 점선 안내
- 완성하면 **색종이 28조각이 물리(중력·회전)로 터지는 축하 애니메이션** + 칭찬 문구 + 이모지 확대
- A~Z 카드마다 **그 글자로 시작하는 단어 이모지**(A🍎 Apple, B🐻 Bear … Z🦓 Zebra).
  글자와 단어를 TTS로 읽어 준다(대문자/소문자 전환 가능).
- 완성한 글자는 카드가 노랗게 칠해지고 ⭐ 표시, 홈에는 `0/52` 진행도

첫 완성 시 +5 XP와 **쓰기 영역 실력 반영** — 알파벳 연습이 v1.2의 실력 대시보드와 연결된다.
DB는 v3으로 올리며 `letters` 테이블 추가(기존 데이터 보존).

단위테스트 6건 추가: 26자 완비·단어가 해당 글자로 시작하는지·**모든 획이 그릴 수 있는 형태인지**
(점 2개 이상, 길이 하한, 좌표 범위) ·진행도 키 52개 유일성. 손으로 찍은 좌표라 오타가 나기 쉬워서
데이터 검증을 테스트로 못 박아 뒀다.

실기기에서 A의 첫 획을 그어 인식·전진(1/3획 → 2/3획)까지 확인했다.

## v1.4: 용돈 지갑 · 상점 · 현금 지급

아이 동기부여를 위해 **문제를 풀면 실제 돈(원)이 쌓이고, 부모가 현금으로 바꿔 주는** 구조를 넣었다.
요구는 명확했다: "한 문제 깨면 10원, 최대한 모으기 힘들게."

### 파밍을 막는 게 설계의 전부

10원/문제를 그냥 주면 아이는 **가장 쉬운 레슨을 무한 반복**한다. 그래서 세 겹으로 막았다.

1. **첫 시도 정답만** 계산 — 틀렸다가 맞히면 0원
2. **레슨 첫 클리어에만 지급** — 같은 레슨을 다시 풀면 0원 (결과 화면에 "이미 깬 레슨이라 용돈은 없어요")
3. **보너스에 하루 한도** — 오답 복습 50원은 하루 3회까지, 목표 달성 100원은 하루 1회

12문제를 다 맞힌 레슨 한 판 = 120 + 퍼펙트 30 = **150원**. 10,000원을 모으려면 새 레슨을
70판 가까이 완벽하게 풀어야 한다. 콘텐츠 전체(14,752문제)를 다 풀어도 이론상 최대 15만 원 수준이라
자연스러운 상한이 있다. 이 규칙들은 테스트로 못 박아 뒀다(`WalletTest`: 한 판 200원 이하,
10,000원에 60판 이상, 보너스만으로 하루 500원 이하, 최저가 상품 > 레슨 한 판 보상).

적립: 레슨 첫 클리어(첫 시도 정답×10 + 퍼펙트 30) · 알파벳 한 글자 50원 ·

학년이 트랙, 단원이 유닛이다. 홈에서는 유치원·초등 / 중학교 / 고등학교로 묶어 보여준다.

문제 유형을 늘리는 대신 **단일 `Question.Math` 에 "그림 명세(visual)"와 "입력 방식(input)"을
필드로** 뒀다. 새 그림이 필요하면 `MathVisualView` 에 그리는 법만 추가하면 된다.

| 그림 | 쓰임 |
|---|---|
| `emoji` / `emoji_op` / `array` | 수 세기, 그림 덧셈뺄셈, 곱셈 배열 |
| `shapes` / `angle` | 도형 알아보기, 각도 |
| `clock` | 시각 읽기 (시침·분침·분눈금까지 그린다) |
| `fraction` | 분수를 원으로 나눈 그림 |
| `number_line` / `bar_graph` | 수직선, 자료 해석 |

전부 **이미지 파일 없이 Canvas 와 이모지로** 그린다. 입력은 아이용 큰 숫자 키패드(`NumberPadView`),
2×2 큰 버튼 4지선다, 식 입력 세 가지다. 한국어 TTS로 문제를 읽어 준다.

채점기(`MathGrader`)는 **0.75 = 3/4 = 6/8, "12 cm" = 12, "1,200" = 1200** 을 모두 같은 답으로
인정한다. 테스트가 **모든 숫자 문제의 정답이 자기 채점기를 통과하는지** 전수 확인한다 —
생성기 오타를 잡는 그물이다.

### 초등영어 놀이터 (신규 코스, 648문제)

"알파벳부터 게임처럼"이라는 요구에 맞춰 영어 트랙 맨 앞에 새 코스를 넣었다.
알파벳 찾기 → 대소문자 짝 → 알파벳 소리 → 파닉스 첫소리·모음 → 그림 낱말 → 사이트워드 →
단어 쓰기 → 문장 읽기·말하기·받아쓰기까지 13단계. 그림 문제는 `Mcq` 에 `bigEmoji` 필드를
추가해 **이모지를 76sp로 큼직하게** 띄운다.

### 알파벳 반복 쓰기

한 번 쓰면 끝나던 것을 **여러 번 쓸수록 별이 늘도록** 바꿨다(1회 ⭐ / 3회 ⭐⭐ / 5회 ⭐⭐⭐).
완성 화면 버튼이 "↻ 지우기"에서 "✏️ 한 번 더 쓰기"로 바뀌고, 카드에 "⭐⭐ 3번" 처럼 표시된다.
반복 쓰기도 소액(3원, 5회까지)을 준다.

### 용돈 금액 조정

"문제당 50원은 너무 크다"는 지적을 반영해 **문제당 1~10원 범위**로 낮췄다.
알파벳 한 글자 50 → 10원, 퍼펙트 30 → 20원, 복습 50 → 20원, 목표 달성 100 → 50원,
레벨테스트 200 → 100원. 12문제 퍼펙트 한 판이 140원이다.

### 만들면서 잡은 것

- **선택지 중복**: 생성기 검증이 `⭐🐰⭐🐰⭐ 다음은?` 문제에서 오답이 겹치는 걸 잡아냈다.
  `choiceQ` 가 서로 다른 4개를 못 만들면 `null` 을 돌려주고 다른 난수로 다시 뽑게 고쳤다.
- **듣기 문제가 통째로 사라짐**: 중복 제거 키를 `prompt` 로만 잡았는데 듣기 문제는 prompt가
  "무엇이 들렸나요?"로 고정이라 26개가 1개로 줄어 유닛 2개가 통째로 없어졌다.
  키에 `tts`·정답을 포함시켜 해결.
- **문장제 0문제**: 대시보드에 "🧩 문장제" 영역을 만들어 놓고 문제를 안 만들어서 영영 Lv.0이
  될 뻔했다. 학년별 문장제 생성기(`tools/math/word.js`)를 따로 만들어 1,280문제를 채웠다.

## v2.1: 수학 연습장 (문제 위에 필기)

"식도 써야 하니까 그림에 낙서하듯 풀 수 있으면 좋겠다"는 요구. 수학은 머릿속으로만 풀 수 없다.

`ScratchPadView` 를 문제 화면 **위에 겹치는 투명 오버레이**로 만들었다. 별도 흰 종이가 아니라
투명이라서 **시계·도형·분수 그림 위에 바로 표시하며** 풀 수 있다(각도에 선 긋기, 분수 조각에
동그라미 치기 같은 것). 상단 `📝 연습장` 버튼으로 켜고 끈다.

구현은 **획 목록 + 비트맵 재생성** 방식이다. 획을 리스트로 들고 있다가 비트맵에 그리고,
되돌리기는 마지막 획을 빼고 전부 다시 그린다. 지우개는 비트맵에 `PorterDuff.CLEAR` 로 진짜
지운다(투명 배경이라 배경색으로 덮는 방식은 쓸 수 없다). 소프트웨어 레이어로 강제해서
CLEAR 합성이 기기와 무관하게 동작하게 했다. 빠르게 그을 때 선이 끊기지 않도록
`MotionEvent` 의 history 좌표까지 이어 붙인다(알파벳 쓰기에서 배운 것과 같은 함정).

도구는 **두 줄**로 배치했다. 윗줄에 검정·빨강·파랑 펜(글자 없는 42dp 색 버튼)과
🧽 지우개 · ↩ 되돌리기 · 🗑 모두 지움, 아랫줄에 폭을 다 쓰는 `✅ 다 썼어요` 버튼.
문제를 넘어가면 자동으로 비워지고, 채점 결과가 뜰 때는 가리지 않도록 접힌다.
연습장은 수학 문제에서만 나타난다.

첫 빌드 후 실기기에서 두 가지를 발견해 고쳤다.
- 도구 버튼이 좁아 **"완료"가 두 줄로 깨졌다**. 한 줄에 7개를 욱여넣은 게 원인 —
  폭을 계산해 보니 완료에 50dp밖에 안 남았다. 한 줄로는 어떻게 배치해도 빠듯해서
  **두 줄로 나누는 쪽**을 택했다. 아이가 누르기도 더 쉽다.
- `54 ÷ 6 = ?` 문제인데 라벨이 **"✖️ 곱셈"** 이었다. 배열 그림을 곱셈·나눗셈이 함께 쓰는데
  그림 종류만 보고 라벨을 정했기 때문 → 문제의 기호(÷, -)를 함께 보도록 수정

## v2.2: 수학 과목 마무리 (배치고사 · 해금 · 시작 성능)

v2.0에서 수학을 붙이며 **끝까지 잇지 못한 배선 세 곳**이 있었다. 폰 없이 코드만 보고 잡았다.

### 1. 수학 레벨테스트가 영어 문제를 냈다 (제일 심각)

홈 배너는 "🎯 수학 레벨테스트로 내 학년 찾기"라고 말하면서, `PlacementActivity` 는
`subject` 를 **받기만 하고 쓰지 않았다**. 영어 팩(`placement.json`)을 열고, 1~10 레벨로 판정하고,
결과를 영어 배치 키(`placement_level`)에 덮어썼다. 즉 수학 레벨테스트를 보면 영어 문제가 나오고
영어 배치 결과가 망가졌다.

과목별로 갈라 고쳤다.

| | 영어 | 수학 |
|---|---|---|
| 문제 팩 | `placement.json` | `math_placement.json` |
| 단계 수 | 1~10 | 1~13 (학년) |
| 결과 이름 | "중학 1학년" 같은 수준 | "초등 3학년 수학" 같은 학년명 |
| 저장 키 | `placement_level` / `placement_done` | `math_placement_level` / `math_placement_done` |

수학 배치고사는 숫자 답 문제가 섞여 있는데, 배치고사는 빠르게 넘겨야 하므로 키패드 대신
**정답 주변 수로 보기 4개를 만들어** 선다형으로 낸다(`numericOptions`).

### 2. 배치 결과가 수학 학년을 열어 주지 않았다

해금 로직이 `trackId == "basic"` 일 때만 배치 레벨을 봤다. 수학은 학년이 곧 트랙이라
**배치 학년 이하의 트랙은 모든 단원을 연다**로 확장했다.

### 3. 시작 화면이 팩 22개를 전부 파싱했다

`SubjectActivity` 가 과목별 진행률(`0 / 1495 레슨`)을 보여주려고 **모든 트랙의 팩을 열었다**.
영어만 있을 때는 9개였지만 수학까지 22개, 약 27,000문제가 되면서 앱을 켤 때마다 메인 스레드에서
수 MB를 파싱하는 구조가 됐다 — ANR 직전이다.

`tools/gen_index.js` 가 팩을 훑어 **레슨·문제 수만 담은 `packs/index.json`** 을 굽고,
시작 화면은 이 작은 색인만 읽는다. 완료한 레슨 수는 DB에서 세는데, 수학 레슨 id 가 `ml` 로
시작하는 것을 이용해 과목을 가른다. **콘텐츠를 재생성하면 `gen_index.js` 를 반드시 다시 돌려야 한다**
(테스트가 색인 누락을 잡는다).

### 그 밖에

- **통계 화면**이 영어 6영역만 보여줬다 → 📘 영어 / 🔢 수학 제목을 달고 12영역 모두 표시
- **수학 배지 5종 추가**(총 24종): ➕ 계산왕, 🔺 도형 박사, 🧩 문장제 해결사, 🧮 수학 만능,
  🎓 두 과목 척척. 배지 판정에 두 과목 영역을 모두 넘기도록 수정
- 단위테스트 5건 추가(`PlacementSubjectTest`): 과목별 레벨 범위·저장 키 분리, 두 배치고사 문제가
  겹치지 않는지, **색인이 모든 트랙을 담고 있는지**

를 돌린 뒤, 진행 중이면 `postInvalidateOnAnimation()` 으로 다음 프레임을 스스로 예약한다.
별도 스레드나 라이브러리 없이 부드러운 애니메이션이 나온다.

- **풍선**: 아래에서 떠오르며 좌우로 흔들린다(sin 파). 터뜨리면 색 조각 14개가 중력을 받고
  튀어나간다. 정답 풍선이 화면 위로 도망가면 놓친 것 — 그래서 **서두르게 된다.**
- **바구니**: 사물을 끌면 살짝 커지고, 바구니에 들어가면 격자에 정렬되며 작아진다.
  잘못 담았으면 밖으로 끌어내면 제자리로 돌아간다. 담은 개수가 바구니에 실시간 표시된다.
- **선 잇기**: 왼쪽 점에서 끌면 선이 손가락을 따라오고, 맞는 짝에 놓으면 색이 칠해지며 고정된다.
  틀리면 그 칸이 좌우로 흔들린다(sin 감쇠).

### 재미 요소

목숨 3개 · 90초 타이머 · 점수 · 별 3단계. 목숨이 다하거나 시간이 끝나면 결과 화면이 뜬다.
난이도 3단계(쉬움/보통/어려움)를 놀이터에서 고르고, 어려울수록 풍선이 빨리 떠오른다.

### 게임이 공부보다 돈이 되면 안 된다

게임에도 용돈을 주되 **하루 3판까지, 한 판 최대 20원**으로 묶었다.
하루 게임 용돈 최대 60원인데 레슨 한 판(퍼펙트)이 140원이라 **공부가 항상 더 이득**이다.
이 관계를 테스트로 못 박아 뒀다(`게임이 공부보다 돈이 되면 안 됨`).
반면 **XP와 실력 반영은 제한 없이** 준다 — 게임도 진짜 연습이기 때문이다.

### 테스트로 잡은 게임 특유의 함정

게임은 화면 없이 검증하기 어렵지만 **문제 생성 규칙은 순수 로직**이라 전수 검사가 된다.
단위테스트 9건을 붙였다.

- **정답이 보기에 없으면 영원히 못 깬다** → 모든 난이도에서 200판씩 돌려 정답 포함 확인
- **뺄셈 답이 음수면** 아이가 혼란스럽다 → 답이 0 이상인지 검사
- **선 잇기에서 답이 겹치면** 어느 쪽에 이어도 맞아 버린다 → 4쌍의 답이 모두 다른지 검사

## v2.4: 효과음 줄이기 + 일반 문제도 만지는 재미로

두 가지 피드백이 왔다. **"효과음이 너무 커서 말하기·듣기 소리가 안 들린다"**,
**"놀이터의 상호작용 방식이 좋은데, 별도 메뉴가 아니라 일반 문제에도 있어야 재미있겠다."**

### 효과음이 음성을 덮고 있었다

`SoundPool.play(id, 1f, 1f, …)` — **볼륨 100%로 재생**하고 있었다. 영어 발음(TTS)과 겹치면
효과음이 이긴다. 학습 앱에서 이건 기능을 망치는 수준의 문제다.

기본값을 **30%** 로 낮추고, 설정에 `🔔 효과음 크기` 슬라이더(0~100%)를 넣었다.
소리를 줄여도 **틀렸을 때 진동은 남겨** 피드백이 사라지지 않게 했다.
테스트로 기본값이 40% 이하이면서 0은 아님을 못 박았다.

### 놀이터의 조작을 일반 문제로

게임을 별도 메뉴에 가둬 두면 "공부는 지루한 것, 게임은 재미있는 것"으로 갈린다.
그래서 **문제 풀이 화면 자체**를 만지는 방식으로 바꿨다.

**1. 4지선다 → 둥둥 떠다니는 버블**

보기 4개가 2×2로 배치되어 sin 곡선을 타고 천천히 위아래로 흔들린다. 탭하면 살짝 커졌다
돌아오고(pop), 채점하면 정답은 초록·내가 고른 오답은 빨강으로 밝혀진다.

놀이터의 풍선과 결정적으로 다른 점: **시간 압박이 없다.** 풍선은 놓치면 도망가지만
버블은 사라지지 않는다. 생각할 시간은 그대로 두고 **화면의 움직임과 터치감만** 더한 것이다.

**2. 짝 맞추기 → 손가락으로 선 잇기**

탭-탭 방식이던 매칭 문제를 놀이터의 `LineMatchView` 로 교체했다. 왼쪽에서 끌면 선이 손가락을
따라오고, 맞으면 색이 칠해지며 고정되고 틀리면 그 칸이 흔들린다. **놀이터와 같은 조작이라
아이가 한 번 익히면 어디서든 통한다.**

### 긴 보기는 버블에 넣지 않는다

모든 보기를 버블로 만들면 문장형 보기("나는 사과를 좋아해요.")가 동그라미 안에 뭉개진다.
그래서 짧은 보기만 버블로 보내고 긴 것은 기존 버튼 목록으로 남긴다.

여기서 **테스트가 실제 버그를 잡았다.** 처음엔 글자 수(≤12자)로 판정했는데,
`"나는 사과를 좋아해요."` 는 11자라 "짧은 보기"로 통과해 버렸다. 한글은 알파벳보다 두 배 넓다.
**폭 점수**(한글·한자·가나·이모지 2칸, 나머지 1칸, 상한 12)로 바꿨다.

한 번 더 걸렸다 — 🍎 는 char 두 개(서로게이트 페어)라 4칸으로 계산됐다.
**코드포인트 단위로** 세도록 고쳤다.

결과: 전체 문제 중 **6,527개가 버블**, 864개(문장형)가 목록으로 나온다.

단위테스트 6건 추가(`InteractionTest`): 효과음 기본값 범위, 버블 판정, 폭 점수 계산,
**실제 팩에서 버블이 충분히 쓰이는지·전부 버블이 되지는 않는지**, 짝 맞추기 5쌍 무결성.

### 덤: 레슨 지도가 깨져 있었다 (v1.0부터 있던 버그)

설치 후 확인하다가 **레슨 지도의 동그란 노드가 가로로 늘어난 타원**으로 그려지는 걸 발견했다.
원인은 `FlowLayout.onMeasure` 가 자식의 `layoutParams` 를 무시하고 무조건
`AT_MOST / UNSPECIFIED` 로 재고 있었던 것 — 72×72dp 로 지정해도 버튼이 자기 최소 폭까지
부풀어 올랐다. 단어 타일(wrap_content)에서는 문제가 없어서 여태 안 보였다.

크기를 지정한 자식은 `EXACTLY` 로, wrap_content 인 자식만 기존처럼 재도록 고쳤다.
버튼의 기본 최소 폭·패딩도 0으로 눌렀다.

## v2.5: 수학도 진짜 만지게 (자동 읽기 끄기 · 짚어 세기 · 저학년 버블)

두 가지 지적이 왔다. **"수학 TTS가 누르기 전에 먼저 재생된다"**,
**"모든 문제에 상호작용이 있다더니 초3 나눗셈엔 전혀 없다."**

두 번째는 확인해 보니 맞는 말이었다. v2.4에서 버블을 붙인 건 `input == "choice"` 인 문제뿐인데,
**수학은 대부분 `input == "number"`(숫자 키패드)** 다. 그래서 `54 ÷ 6 = ?` 같은 문제는
펭귄 그림이 **정지 이미지**로 떠 있고 키패드만 두드리는, v2.3 이전과 똑같은 화면이었다.
"모든 문제에 적용했다"는 내 설명이 실제와 달랐다.

### 1. 문제를 열자마자 읽어 주지 않는다

`autoReadMath` 를 꺼서 🔊 버튼을 누를 때만 재생한다. 갑자기 소리가 나오는 게 방해가 된다는
지적이 맞다.

### 2. 그림을 손가락으로 짚어 세기

정지 그림이던 이모지·배열을 **하나씩 터치할 수 있게** 했다. 짚을 때마다 초록 동그라미에
**세는 순서(1, 2, 3…)가 붙고**, 위에 "👆 지금까지 N개 세었어요"가 뜬다. 다시 누르면 취소되고,
`다시 세기` 로 초기화한다.

아이가 실제로 손가락으로 짚으며 세는 행동을 그대로 옮긴 것이라, 수 세기·곱셈 배열·나눗셈
묶음에서 그림이 **읽는 대상이 아니라 만지는 도구**가 된다.

### 3. 저학년 숫자 답은 키패드 대신 버블

유치원~초3 의 숫자 답 문제(정수 0~200, 단위 없음)는 **버블 4개를 탭**하는 방식으로 바꿨다.
보기는 앱이 정답 주변 수로 만든다(`MiniGames.wrongNumbers`). 실제 콘텐츠 기준
**저학년 숫자 문제 2,418개가 버블**, 1,240개(분수·소수·단위 있는 답)는 키패드로 남는다.

초4 이상은 직접 계산해 써 보는 게 중요하므로 **키패드를 유지**한다 — 재미를 위해 학습을
망치지 않도록 선을 그었다.

단위테스트 1건 추가: 저학년 숫자 답으로 **보기 4개를 실제로 만들 수 있는지**(중복 없이,
정답 포함) 전수 확인.

## v2.6: 끌어서 답하기 (삐약 소리 줄이기 · 시계 바늘 · 끌어서 나누기)

**"삐약 소리를 더 작게. 그리고 문제 풀면서 상호작용할 만한 게 더 없을까?
정답 고르는 버블은 매우 좋은데, 예를 들면 펭귄을 드래그해서 이동한다거나."**

버블(탭)이 좋았다면 다음 단계는 **끌기(드래그)** 다. 탭은 "고른다"까지고,
끌기는 **직접 만들어 낸다**. 그래서 그림이 답을 *보여주는* 게 아니라
**답을 *만드는 도구*** 가 되는 두 가지를 넣었다.

### 1. 삐약 소리를 더 작게

`Sfx.piyak()` 은 이제 배율 **0.8 → 0.25**. 이 소리는 버블을 고를 때, 그림을 짚을 때,
바늘을 돌릴 때마다 울리기 때문에 정답·오답 소리와 같은 크기면 금세 시끄러워진다.
숫자를 `Sfx.TAP_VOLUME_SCALE` 상수로 빼서 **정답 소리보다 반드시 작다**는 걸
단위테스트로 고정했다.

### 2. 🕐 시계 바늘 돌리기 (`clock_set`)

시각을 **읽고 숫자로 답하는** 문제 옆에, **직접 바늘을 돌려 만드는** 문제를 새로 넣었다.

- 시계 안쪽을 잡으면 **짧은바늘(시침)**, 바깥쪽을 잡으면 **긴바늘(분침)** 이 손가락을 따라온다
- 분은 **5분 단위로 딱 붙는다** — 아이 손가락으로 1분 단위를 맞추는 건 무리다
- 지금 맞춘 시각이 시계 밑에 "3시 30분" 으로 계속 보인다
- `12시로` 버튼으로 되돌린다

초1(정각·30분) **72문제**, 초2(5분 단위) **72문제**.

### 3. 🧺 끌어서 똑같이 나누기 (`group`) — 사용자가 제안한 그 드래그

지적받았던 **초3 나눗셈**에 붙였다. `18 ÷ 3` 을 머리로 계산하기 전에,
펭귄 18마리를 **손으로 끌어다 바구니 3개에 나눠 담아 본다**.

- 사물을 잡아 끌면 커지면서 따라오고, 바구니 안에 놓으면 줄 맞춰 정렬된다
- 바구니 밖에 놓으면 원래 자리로 돌아간다
- 위에 "🧺 4개 · 4개 · 3개 (남은 것 2개)" 처럼 **현재 상태가 실시간으로** 보인다
- 채점은 **다 담았고 + 바구니마다 개수가 같을 때** 만 정답.
  덜 담았는지 개수가 다른지에 따라 **틀린 이유가 다르게** 나온다

전체 개수는 18개 이하, 바구니는 2~4개로 제한했다(화면에 한눈에 들어오는 만큼).
**88문제.**

### 이걸 위해 만든 것

| 구조 | 설명 |
|---|---|
| `input = "visual"` | 그림 자체가 답을 받는 새 입력 방식. 키패드도 보기도 뜨지 않는다 |
| `MathVisual.CLOCK_SET` | 기존 시계 그리기를 재사용하고 각도 → 시·분 변환만 추가 |
| `MathVisual.GROUP` | 새 `GroupDragView` 가 그린다 (`BasketGameView` 의 드래그 방식 재사용) |
| `V.clockSet` / `V.group` | 생성기 쪽 그림 명세 |

`GroupDragView` 는 화면이 다시 재어져도(연습장 토글 등) **이미 담아 놓은 걸 잃지 않는다** —
자리만 다시 잡는다.

### 검증

단위테스트 **2건 추가 (총 84건, 전부 통과)**

- 시계 답이 `H:MM` 꼴이고 **분이 5의 배수**인지 (아니면 손가락으로 맞출 수 없다)
- 나눠 담기가 **똑같이 나눠떨어지고**, 답이 몫과 일치하고, 개수가 화면 범위(4~18)인지
- 톡톡 소리가 정답·오답 소리보다 작은지

수학 총 문제 수 **12,034 → 12,266** (신규 232문제), 전체 **27,716문제**.

## v2.7: 분수 색칠 + 도형 분류

v2.6 끝에 적어 둔 후보 중 **분수 색칠**과 **도형 분류** 두 가지를 골라 넣었다.
`input = "visual"` 구조가 이미 있어서 각각 **뷰 로직 + 생성기 한 단원**으로 끝났다.

### 1. 🍰 분수만큼 색칠하기 (`fraction_paint`)

기존 분수 문제는 **색칠된 그림을 보고 분수를 답하는** 방향이었다. 이걸 **반대로** 뒤집었다.

> "전체를 똑같이 8로 나눈 그림이에요. **3/8 만큼 색칠해 보세요.**"

- 원 조각을 **누르면 칠해지고 다시 누르면 지워진다**
- 그림 밑에 "칠한 칸 3 / 8" 이 계속 보인다
- 채점은 **칠한 칸 수 == 분자**. 틀리면 "2칸 더 칠해야 해요" / "1칸을 더 칠했어요" 로
  **모자란 건지 넘친 건지** 구분해서 알려준다

기존 `drawFraction` 을 그대로 쓰고 **각도 → 조각 번호 변환만** 추가했다.
초3 분수 45문제 + **소수 색칠** 5문제(`0.4` 를 10칸 중 4칸으로 — 소수와 분수가 같은 것임을
손으로 확인한다).

### 2. 🔺 도형 분류하기 (`shape_sort`)

이름이 붙은 바구니에 도형을 **끌어 담는다**.

핵심은 **같은 종류라도 색과 방향을 다르게** 섞은 것이다(삼각형 🔺🔻🔼🔽, 사각형 🟥🟦🟩🟨,
원 🔴🔵🟢🟡). 똑같은 그림을 짝짓는 게 아니라 **모양을 보고 분류**해야 한다.
문제 안에서 순서도 섞어서, 위에서부터 차례로 담으면 맞아 버리는 일이 없다.

- 유치원: 바구니 **2개** × 3개씩 (6세는 두 가지부터) — 96문제
- 초3 평면도형: 바구니 **3개** × 3개씩 — 96문제

## v2.8: 수직선 · 저울 · 각도 · 그래프

남아 있던 후보를 네 가지 모두 넣었다. 이제 **손으로 조작하는 문제가 883개**,
종류로는 **8가지**다.

### 1. 📏 수직선에서 찾기 (`number_line_drag`)

파란 점을 끌어 수직선 위의 자리를 짚는다. 눈금에 딱 붙어서 손가락으로도 정확히 맞는다.

| 어디 | 범위 | 눈금 |
|---|---|---|
| 초1 | 0~20 | 1 |
| 초2 | 0~100 | 5 |
| 초3 | 0~1 | 0.1 (소수가 0과 1 사이 어디쯤인지) |
| 중1 | -10~10 | 1 (음수가 0의 **왼쪽**이라는 감각) |

기존 수직선 그리기가 **눈금 간격을 1로 고정**하고 있어서 소수·음수 수직선에서는 숫자가
틀리게 찍혔다. 구간 수를 받아 쓰도록 고치고, 눈금이 촘촘하면 숫자를 한 칸 건너 적게 했다.

### 2. ⚖️ 저울로 방정식 풀기 (`balance`)

`3x + 2 = 11` 을 저울로 만든다. 왼쪽 접시에 x 상자 3개와 1짜리 추 2개, 오른쪽에 추 11개.
**아래 손잡이를 끌어 x 값을 바꾸면 저울이 실시간으로 기운다.**

- "왼쪽이 더 무거워요" → "오른쪽이 더 무거워요" 를 오가다 딱 맞으면 **수평 + "평형이에요!"**
- 이항을 외우기 전에 **"양쪽이 같다"** 는 등식의 뜻을 눈으로 본다
- 중1 일차방정식 120문제

### 3. 📐 각도 만들기 (`angle_set`)

각도를 **재는** 대신 **만든다.** 파란 손잡이를 돌리면 5° 단위로 붙고, 만든 각이 숫자로 뜬다.
틀리면 "조금 더 벌려야 해요 / 좁혀야 해요" 로 방향을 알려준다. 초4 30문제.

### 4. 📊 그래프 세우기 (`bar_build`)

표를 주고 **막대를 끌어 올려** 그래프를 완성한다. 손가락 높이가 곧 막대 높이(칸에 딱 붙음).
맞은 막대는 이름이 초록색으로 바뀐다. 초2·초4 192문제.

### 겸사겸사 고친 것

- **연습장이 그림을 덮는 문제** — 조작하는 그림 위에 필기 오버레이가 열리면 끌 수가 없다.
  `input = "visual"` 문제에서는 연습장 버튼을 감춘다
- **중1 수직선에서 답이 -10 인 문제** — 점이 처음 놓인 자리라 **안 움직여도 맞아 버렸다.**
  생성기에서 제외하고, 테스트가 다시 못 들어오게 막는다

### 검증

단위테스트 **84건 전부 통과**. 새로 확인하는 것:

- 수직선 — 답이 **눈금 위에 있는 값**인지(없으면 손가락으로 못 맞춘다), 시작 위치와 다른지
- 각도 — 5° 단위인지, 그림의 각도와 답이 같은지
- 저울 — **그 x 에서 실제로 평형이 되는지**(`a·x + b == c`), 추가 45개를 넘지 않는지
- 그래프 — 막대가 3~5개에 높이 1~9인지, 답이 막대 높이와 일치하는지

수학 **12,508 → 12,917문제**, 전체 **28,367문제**.

## v2.9: 토끼·펭귄을 손으로 옮기기

**"초등 수학에서 아이콘 쓰잖아. 토끼나 펭귄 이런 거 드래그해서 옮기게끔은 못 만드는 거야?
그렇게 옮겨서 할 수 있으면 더 편할 거 같은데, 초딩이 하기에."**

맞는 지적이었다. v2.5에서 넣은 건 **짚어서 세기(탭)** 뿐이라 그림 자체는 **못 움직였다.**
아이 입장에서는 화면 위의 펭귄이 종이에 인쇄된 것과 똑같았던 셈이다.

### 1. 그림의 아이콘을 그냥 끌 수 있게

이모지 그림(`emoji`, `emoji_op`)의 **낱개를 손가락으로 끌어 아무 데나 옮길 수 있다.**

- **톡 누르면** 전처럼 세어지고(초록 번호), **끌면** 옮겨진다
- 끄는 중인 것은 조금 커지면서 **맨 위에 그려져** 다른 것에 가리지 않는다
- 손가락이 10dp 넘게 움직여야 "끌기"로 본다 — 안 그러면 세기가 안 눌린다
- `처음으로` 를 누르면 센 것과 옮긴 것이 함께 되돌아간다

세다가 헷갈리면 **센 것을 옆으로 밀어 두면 된다.** 종이 위에서 손으로 하던 걸 그대로 옮긴 것이다.

곱셈 배열(`array`)은 **일부러 뺐다.** 행·열로 놓인 **자리 자체가 뜻**이라
(3줄 × 4개 = 12) 옮기면 안내선과 어긋난다. 배열을 나누는 건 이미
v2.6의 `끌어서 똑같이 나누기` 가 맡고 있다.

### 2. 📦 모으기 · 덜어내기 (`gather`)

"끌 수 있으면 더 편하겠다"는 말의 핵심은 **답을 계산하지 않고 옮기다 보면 나오는 것**이라
생각해서, 덧셈·뺄셈을 아예 그렇게 바꾼 단원을 만들었다.

| 단원 | 무엇을 하나 | 답 |
|---|---|---|
| 유치원 `옮기면서 세기` | 3~8마리를 상자에 하나씩 옮긴다 | 옮긴 개수 |
| 초1 `모아서 더하기` | `3 + 4` → 일곱 마리를 **한 상자에 모은다** | 상자 안의 수 |
| 초1 `덜어내고 빼기` | `8 - 3` → 세 마리를 **집으로 보낸다** | 밖에 남은 수 |

- 위에 "📦 모은 것 5마리 · 아직 2마리" 처럼 **지금 상태가 실시간으로** 보인다
- 뺄셈은 **정확히 뺄 만큼만** 보내야 정답 — 다 보내면 틀린다
- 상자 밖에 놓으면 제자리로 돌아간다

`GroupDragView` 에 바구니 하나짜리 모드를 더한 것이라 새 뷰는 만들지 않았다.
바구니가 하나면 아주 넓어서, 한 줄에 몇 개가 들어갈지 폭을 보고 정하도록 고쳤다.

**288문제.**

### 테스트가 잡아 준 것

`1 + 1` 이 **두 마리를 옮기는 문제**로 만들어지고 있었다. 드래그 연습으로는 의미가 없어서
합이 3 이상일 때만 내도록 했다. (테스트가 "화면에 안 들어갈 만큼 많다"는 범위 검사에
걸려서 발견됐다 — 하한도 같이 보고 있었다.)

단위테스트 **85건**(1건 추가, 전부 통과). 새로 확인하는 것:

- 옮겨 담기 — 담을 개수가 전체보다 많지 않은지, 답이 **옮긴 결과와 일치**하는지
  (모으기면 전체, 덜어내기면 남은 것), 3~10마리인지
- 끌 수 있는 그림이 **낱개 이모지뿐**이고 곱셈 배열은 빠져 있는지

수학 **12,917 → 13,205문제**, 전체 **28,655문제**.

## v2.9.1: 실기기에서 본 배치 어긋남 3건

드디어 실기기에서 `끌어서 똑같이 나누기`(초3, `16 ÷ 4`)를 눈으로 봤다.
**코드로는 안 잡히고 화면을 봐야만 아는 것 3건**이 한 화면에 다 있었다.

| 무엇이 어긋났나 | 왜 | 어떻게 고쳤나 |
|---|---|---|
| 토끼들이 **세로로 겹침** — 아랫줄 귀가 윗줄을 파고듦 | 줄 간격을 글자 크기의 1.05배로 잡았는데, **이모지 글리프는 지정 크기보다 위아래로 더 튀어나온다** (특히 귀·꼬리) | 간격을 **1.32배**로 (`ROW_STEP` 상수), 그만큼 이모지 크기도 줄여 칸 안에 맞춤 |
| 바구니 이름 **`1번 (0)` 이 칸 밖으로 넘침** | 글자 크기를 **이모지 크기**에 맞췄는데, 바구니 4개면 칸 폭이 이모지보다 훨씬 좁다 | 글자 크기를 **바구니 폭 기준**으로 (`min(이모지×0.45, 바구니폭×0.20)`) |
| 이름과 개수가 한 줄이라 더 넘침 | `1번 (0)` 을 한 덩어리로 그림 | **이름은 위, 개수는 아래**로 분리. 담기면 개수가 주황색으로 바뀐다 |

세 번째는 덤으로 읽기도 좋아졌다 — 개수가 크고 색이 바뀌니 "지금 몇 개 담았나"가 한눈에 든다.

이 세 가지는 **단위테스트로는 절대 못 잡는다.** 값이 틀린 게 아니라 화면에서 겹칠 뿐이라,
그려 보기 전에는 알 수 없다. 배치 상수(`ROW_STEP`, 글자 크기 계산)는 한곳에 모아 뒀으니
다른 기기에서 또 어긋나면 그 숫자만 만지면 된다.

수정 범위는 `GroupDragView` 하나라, 이 뷰를 쓰는 **끌어서 나누기 · 도형 분류 · 모으기/덜어내기**
세 가지가 함께 고쳐졌다.

  (안 돌리면 시작 화면 진행률이 어긋난다 — 테스트가 잡아 준다).
- 앱을 설치할 때 `applicationId`(`com.piyak.english`)는 **절대 바꾸지 말 것.**
  바꾸면 새 앱으로 설치되어 진행도·지갑·용돈이 전부 사라진다.
